# 日志系统

## 1. 概览

本项目的日志能力由 `crates/utils/kernel_tracer` 和 `crates/kernel/src/tracer/mod.rs` 共同实现

- `kernel_tracer` 定义日志事件、span、级别过滤和 `Tracer` trait
- `kernel` crate 中的 `KernelTracerImpl` 负责把日志实际输出到控制台和可选的文件通道
- 控制台日志写入到 UART 串口中
- 文件日志写入到 VirtIO console，再由 QEMU 落到宿主机文件，因此不依赖内核文件系统
- 日志文件的位置通过 cargo qemu 的参数 `--virtio-log-file` 控制，默认放在 logs 目录下，启动时会输出日志位置

## 2. 日志通道与配置

`kernel_tracer` 把日志分成三类开关：

| 环境变量 | 作用 | 当前实现 |
| --- | --- | --- |
| `KERNEL_CLOG` | 控制台日志级别 | 输出到 UART 控制台 |
| `KERNEL_FLOG` | 文件日志级别 | 输出到 VirtIO console，再由 QEMU 写宿主机文件 |
| `KERNEL_SLOG` | span 级别 | 决定哪些 span 会进入当前 hart 的 span 栈 |

这些变量通过 `option_env!` 在**编译期**读入，因此修改后需要重新构建内核。

支持的有效级别是 `TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`。除此之外的值都会被当作关闭处理；项目里通常用 `NONE` 表示关闭。

可以通过控制 xtask 运行的环境变量，传递到内核构建时。

## 3. 日志数据模型

类似于 log、tracing，使用 `trace!`、`debug!`、`info!`、`warn!`、`error!` 等宏记录日志。

而 span 用来描述一段上下文范围，例如 hart、系统调用、文件系统操作等。典型用法是：

```rust
let _enter = info_span!("hart", id = hart_id).entered();
```

激活后的 span 会根据 `KERNEL_SLOG` 等级进入当前 hart 的 span 栈。

## 4. 文件日志链路

启用文件日志时，qemu 调用会追加下面三组参数，添加 virio console 设备，指定其后端为传入的文件日志路径：

```text
-chardev file,id=kernel_log,path=<path>
-device virtio-serial-device,id=logserial,bus=virtio-mmio-bus.1
-device virtconsole,bus=logserial.0,chardev=kernel_log
```

内核启动时会初始化设备 (`crates/kernel/src/drivers.rs`)，在这一步中通过遍历 FDT 查找 virtio mmio 节点，并按节点类型初始化。
